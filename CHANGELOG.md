# История изменений Employee Attendance API

## Unreleased — 7 ноября 2026 года

Подготовлено для переноса текущей версии из test в main. Релиз на GitHub и Git-тег пока не создавались.

Диапазон исходников: main `c946eaa` → test `b238193` (четыре коммита). Этот changelog оформлен отдельно после коммита b238193.

### Добавлено

- Поиск сотрудника: `GET /employees/{id}` возвращает сотрудника с `200 OK` либо `404 Not Found`.
- Удаление сотрудника: `DELETE /employees/{id}` возвращает `204 No Content` без тела; повторное удаление отсутствующей записи — `404`.
- Валидация CreateEmployeeRequest через Jakarta Validation: обязательное имя, выбранный формат «Имя Фамилия» и обязательная должность.
- Зависимость Spring Boot Validation и запуск проверки запроса через `@Valid`.
- Исключение локальных папок Postman из Git через корневой `.gitignore`.

### Изменено

- Контроллер получает EmployeeService через конструктор и делегирует ему работу с сотрудниками.
- POST принимает CreateEmployeeRequest без клиентского ID; успешное создание возвращает `201 Created` и сохранённого сотрудника с серверным ID.
- Сервис сохраняет сотрудников в ConcurrentHashMap, получает ID через AtomicInteger и возвращает отдельный список для GET.
- Счётчик и карта закрыты полями `private final`.
- ID для поиска и удаления берётся из пути через `@PathVariable`.
- Пробелы по краям имени удаляются в конструкторе запроса перед проверкой ограничений.
- Employee больше не дублирует проверки имени и должности; в конструкторе остаётся проверка положительного ID.

### Исправлено

- Конфликт двух GET-обработчиков одного маршрута: список и поиск по ID имеют разные пути.
- Для найденного сотрудника используется `200`, для удаления — `204`.
- Недопустимый ID возвращает `400`, отсутствующий сотрудник — `404` через ResponseStatusException.
- Проверка отсутствия удаляемого сотрудника использует результат одного `map.remove(id)`, без раздельных get и remove.

### Проверено

- На коммите b238193 повторно выполнен `mvnw.cmd -B test`: BUILD SUCCESS, один тест загрузки Spring-контекста, ошибок нет.
- Перед последним изменением удаления выполнен внешний HTTP-прогон: 53 проверки, 51 успешная, 82 запроса. Подтверждены основные операции, ошибки входных данных, уникальность ID при 12 параллельных созданиях и корректные статусы в одном прогоне параллельного удаления.
- Две проверки строгого строкового формата position выявили известное отклонение, описанное ниже.
- Внешние HTTP-проверки не добавлены в Maven/JUnit. После перехода удаления на один remove полный HTTP-прогон не повторялся; текущий результат Maven не заменяет проверку HTTP-сценариев.

### Известные ограничения

- `position: 0` и `position: "0"` могут преобразовываться в C_DEVELOPER вместо отклонения запроса.
- Данные и счётчик ID находятся в памяти и сбрасываются после перезапуска приложения.
- Порядок списка сотрудников не гарантирован.
- Стандартные ответы об ошибках не содержали прикладного пояснения reason в проверенном HTTP-прогоне.
- Нет изменения сотрудника через PUT/PATCH, реализации смен, PostgreSQL и Kafka.
- В проекте пока один автоматический тест загрузки контекста; тестов HTTP-контракта в репозитории нет.
